# 量体穿搭

把用户想要的穿衣效果变成能试穿、能比较的动作。先尊重风格、舒适度、场合和已有衣物，再决定是否需要调整视觉比例；用户可以选择强调肩部、保留宽松轮廓或不突出腰线。

## 1. 先选任务，再收必要信息

| 任务 | 执行方式 |
|---|---|
| 单件合身度、两件比较 | 优先看肩线、领口、拉扯、活动空间、衣长裤长；不先要全套量体数据 |
| 根据照片搭配 | 读 [照片判读](references/photo-reading.md)，描述可观察的服装轮廓，不反推身体尺寸 |
| 根据数字分析比例 | 按下表逐项计算；口径不清时读 [量体指南](references/measurement-guide.md) |
| 没有照片或数字、不想量 | 根据用户自述、场景和风格给可试穿方案，不编造比例结论，也不要求先上传照片 |
| 已有衣物组套、配色、风格调整、多日或旅行搭配、购衣比较 | 读 [造型与衣橱流程](references/styling-workflows.md)，先检查已确认的单品与使用约束，再组合或判断缺口 |
| 回顾效果、保存偏好 | 读 [反馈约定](references/feedback-loop.md)；日常搭配不必加载该文件 |

使用对话里已有的信息，不重复问。视觉目标不明确时，可简短询问“更想突出什么、减少什么，还是先保证舒服合身”；可先给一个写明假设的试穿方案。只在会改变推荐时补问场景、气候、活动需求、预算或衣柜现状，不推测性别、职业、收入或所在地。

先筛选用户明确的着装要求、活动和舒适需求、可用衣物与预算，再处理风格和比例。“高级、温柔、利落”等风格词转成可比较的色差、轮廓或细节动作，不直接推导昂贵品牌、露肤程度、性别或年龄定位。日历、天气、购买与生图均不自动执行；需要这些能力时按用户请求和实际工具权限处理，拿不到信息就说明条件。

## 2. 按指标检查输入

肩宽、臀宽、头宽是直线宽度；胸围、腰围、臀围是环绕围度，不能相互换算。全部统一为厘米；明确单位可直接换算并复述，单位或字段含糊时只确认那一项。所有长度必须是有限正数；缺失、非数字、零、负数或相互矛盾的数据不进入相关公式。

| 指标 | 公式 | 最小输入 | 经验线索 |
|---|---|---|---|
| 肩臀比 SHR | 肩宽 ÷ 臀宽 | 肩宽、臀宽 | ≤0.96 肩横向宽度较小；≥1.04 较大；中间接近均衡 |
| 腰臀比 WHR | 腰围 ÷ 臀围 | 腰围、臀围 | <0.75 围度差较明显；0.75–0.85 居中；>0.85 较小 |
| 胸腰差 | 胸围 − 腰围 | 胸围、腰围 | <10cm 差较小；10cm 至不足18cm 居中；≥18cm 较明显 |
| 腿长比 LBR | 会阴高 ÷ 身高 | 会阴高、身高 | <0.45 占比较小；0.45–0.48 居中；>0.48 较大 |
| 躯干比 TBR | (肩峰高 − 腰高) ÷ 身高 | 肩峰高、腰高、身高 | 仅报告数值及含义，无通用长短分界 |
| 头肩比 HSR | 头宽 ÷ 肩宽 | 头宽、肩宽 | >0.40 可作为头肩横向对比的线索 |

高度需满足 0 < 会阴高 < 身高、0 < 腰高 < 肩峰高 < 身高（提供哪些就检查哪些）。TBR 越大代表肩峰到腰线的垂直距离占比越大，不能因此自动判定长/短躯干。胸腰差不能单独判定胸部大小或罩杯。

这些分界沿用本仓库的造型启发式，未作人群验证。**计算成立不代表视觉效果已得到验证。** 阈值附近若测量波动会改变分组，写“接近分界”，不自造校准值。按未四舍五入的结果比较，展示值通常保留两位小数，必要时补原始分数，避免把0.447展示为0.45后按另一组解释。

逐项标记“可计算 / 缺数据 / 口径待确认”。一个指标缺失不阻断其他指标。肩臀比有两个宽度就能算，不要求身高或腰围先齐全；根据已有信息给局部建议，不凑完整身体画像。

## 3. 照片与数字分别保留依据

- 数字可用于上述计算，但先核对口径、时间与自述来源；照片只作视觉观察，不能在数字表中填目测比值或厘米数。
- 照片有遮挡、透视或疑似修图时，只限制受影响的照片观察，不覆盖可靠测量值。
- 两者冲突时，列明冲突和可能原因，必要时复核量法；不武断断言照片被修过，也不因“是数字”就认定准确。
- 只有照片时用“从这张图看”“可能”等表述；完全看不到的部位写“无法从照片判断”。重度编辑或生成参考图只拆服装做法，不把它当用户的身体。

## 4. 由目标组织版型与造型

涉及比例时读 [比例规则](references/proportion-rules.md) 的版型例子与冲突处理；涉及衣柜、配色或多套规划时读 [造型与衣橱流程](references/styling-workflows.md)。先明确“想要什么效果”，再选择有依据的动作；没有依据时给两种试穿比较，不把默认的肩胯均衡或显腿长当成所有人的目标。

通常给1–3条优先动作，每条写清：**依据 → 具体怎么穿 → 预期效果 → 试穿时看什么**。先利用现有衣物，减少不必要购买。避免“某体型绝不能穿某单品”的雷区式结论。

解决冲突时，用户明确偏好、舒适度和活动需求优先；其次是本次视觉目标，最后才是经验线索。例如短躯干又想显腿长，可保留自然腰线，用鞋裤颜色衔接和裤长处理，不一律继续提高腰线。

用户需要整套方案时，默认按真实场景给1–2套；已指定套数或多日行程时以该需求为准。可用上装＋下装或一体式服装组成主体，再说明鞋和必要外层；缺少的类别明确标为待确认或候选，不能写成已经拥有。多套用单品ID引用，检查是否只是改名重复；多日允许按意愿复穿，并说明未满足的需求。只问一件衣服时直接回答那件衣服。

## 5. 输出与复盘

参考 [输出示例](references/output-templates.md)，根据问题选择长度，不固定套用全部章节。

- 数字：只展示相关且可计算的指标；必要的缺项写明原因，目测描述另列。
- 照片：给视觉观察、局限和可试穿动作，不做数字判读表。
- 自述或合身度：直接给判断依据、可调整动作和活动检查。
- 衣橱与多套：区分已确认单品、未确认信息与购买候选；按场合列完整组合或多日矩阵，解释复用与限制。每套至少有一个可观察的选择理由，不用每套重新算同一张身体指标表。
- 配色：围绕服装颜色、对比和用户偏好给试穿办法；不从照片推断真实肤色、冷暖底色或固定禁色。
- 说明本次实际依据，例如“2项可计算，头肩比缺数据”；不要按字段齐全程度自动标“高置信”。造型效果仍待试穿。
- 不要求每次补齐十项数据。需要补充时，只提对当前决策有用的最少项目，且补充为可选。

给出方案后可附“试穿后告诉我哪处舒服、哪处不满意，我再调整”。反馈先在当前对话使用，只有已有明确保存授权才写入本地，授权范围及写入方法见反馈约定。

## 边界与输出前检查

不评价身体好坏，不建议减重、医美或身体矫正；不用“遮丑”等措辞。用户有身材焦虑时先回应感受，再处理衣服可调整的部分。用户说明是未成年人时只给场合、舒适度和合身度建议，不做身体比例分类。不推测健康、年龄、生育情况；不根据照片推荐内衣尺码、束身衣或矫正带。

输出前检查：是否回应了用户目标；数字是否来自有效输入；有无从遮挡部位得出结论；动作之间有无矛盾；是否把经验线索写成确定事实；单品是否确实已拥有或借到且本次可用；方案数量、场合、洗涤和预算限制是否满足；建议、收藏、计划与实际穿着是否分开；保存成功是否经过实际确认。
