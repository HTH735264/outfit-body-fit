# 量体穿搭：按身材比例给方案

把「我这个身材适合穿什么」拆成可执行的比例判读 + 版型处方。核心不是身材标签，是**你想在视觉上把重量放在哪**。

## 两个输入通道（不要混用）

| 通道 | 输入 | 能产出 | 置信度 |
|---|---|---|---|
| A 照片 | 全身/半身照 | 视觉轮廓走向、肩胯相对关系、上下身分割位置、头肩比、姿态习惯 | 中 / 低 |
| B 数字 | 肩宽、胸围、腰围、臀围、身高、腰高、会阴高 | 可算的比例指标与幅度 | 高 |

**照片定方向，数字定幅度。** 数字缺失时降级到 A 通道，输出必须标注「视觉印象，非测量结论」，并告诉用户补哪三个数就能升级。

绝不用照片反推围度、身高或体重。绝不给「你应该是 X 型身材」的确定结论——给的是比例特征和对应手法。

## 工作流

### 第 0 步：定档位

| 档 | 输入 | 能算的指标数 | 置信度 |
|---|---|---|---|
| A | 只有照片 | 0，只给视觉方向 | 低 |
| B− | 部分数字（肩宽 / 臀宽 / 腰围 / 身高 缺任意一项） | 1–2 | 中 |
| B | 肩宽、腰围、臀围、身高 | 3 | 高 |
| B+ | B 再加会阴高、胸围、腰高、头宽 | 4–6 | 高 |

三条规则：

1. **至少算出肩臀比和腰臀比**。这两条算不出就整体降到 B−，不进第 3 步的处方映射，只给方向
2. 缺哪个指标就标哪个「不可读」，不要用相近指标替代，也不要猜
3. 照片和数字都有 → 走数字档，照片只用来交叉校验；冲突时以数字为准

### 第 0.5 步：先看照片被修过没有

照片里的比例经常已经被服装和拍摄改过一轮。跳过这一步，后面所有判读都在读一个加工过的结果，而且会读得很有说服力——让人以为"这个人本来就长这样"。

三类修正，命中任意一条就必须在输出开头声明：

| 类型 | 信号 | 被改变的量 |
|---|---|---|
| 服装 | 高腰下装、短款上衣、宽松外套、垫肩 / 泡泡袖 / 落肩、高跟或厚底、深色紧身下装、阔腿微喇 | 腰线位置、肩宽、腿长比、下盘体积 |
| 拍摄 | 仰拍（地平线低于膝）、俯拍、广角近距离、镜面自拍、踮脚扭胯、手插口袋 | 腿长、头肩比、肩线 |
| 图像 | AI 生成水印、皮肤过度平滑、反射不自然、腿线或背景明显拉伸、商用模特图 | 全部 |

处置三条：

1. 命中的条目在输出里**点名列出来**，不藏进脚注
2. 关键信息被直接抹掉的（宽松外套遮腰、手插口袋压肩线、手机挡脸、双脚被裁），该指标写「**不可读**」，不要猜一个值填上
3. 声明句固定用：「以下判断的是照片中呈现的比例，不是原始骨架」

完整清单与话术见 [references/photo-reading.md](references/photo-reading.md)。

### 第 1 步：收数据（缺什么问什么，一次问完）

B 档最小可用集：**肩宽、腰围、臀围、身高**。有胸围、腰高、会阴高更好。

不要一次抛出八个字段的表单。按这个顺序问，问完即止：

1. 肩宽、腰围、臀围、身高（四个数就能定主视觉轴）
2. 够不够 → 不够再要胸围（定胸腰差）、会阴高（定腿长比）
3. 用户不想量 → 直接进 A 档，别劝

量法不清时给 [references/measurement-guide.md](references/measurement-guide.md)。

### 第 2 步：判读

按下面六个指标算，阈值是默认值，遇到极端身高/骨架可校准并在输出里说明：

| 指标 | 算法 | 判读 |
|---|---|---|
| 肩臀比 | 肩宽 ÷ 臀宽 | ≥1.04 肩宽于胯 ｜ ≤0.96 肩窄于胯 ｜ 其间均衡 |
| 腰臀比 | 腰围 ÷ 臀围 | <0.75 腰线明确 ｜ 0.75–0.85 中等 ｜ >0.85 腰线弱 |
| 胸腰差 | 胸围 − 腰围 | ≥18cm 上身有起伏 ｜ <10cm 上身平直 |
| 腿长比 | 会阴高 ÷ 身高 | <0.45 短 ｜ 0.45–0.48 常规 ｜ >0.48 长 |
| 躯干比 | (肩峰高 − 腰高) ÷ 身高 | 越高躯干越长 |
| 头肩比 | 头宽 ÷ 肩宽 | >0.40 头显大、肩显窄 |

**指标优先级**（能算几个先算前几个）：肩臀比 > 腰臀比 > 腿长比 > 胸腰差 > 躯干比 > 头肩比。

**不可读的写法**：缺数据写「不可读」并说明缺什么，不用相近指标替代。例：「躯干比：不可读（缺肩峰高与腰高）」。

判读结果写成**比例特征 + 视觉后果**，不写身材类型名。例：「肩臀比 0.93 → 肩线比胯线窄，视觉重量偏下，容易显得上轻下重」。

### 第 3 步：开处方

三条起步，按视觉影响从大到小排。每条必须是「手法 + 具体单品动作 + 为什么」。

高频六条（完整版见 [references/proportion-rules.md](references/proportion-rules.md)）：

- **肩窄于胯** → 抬高肩线：正肩结构、薄垫肩、船领/方领、上身浅色横条；下装深色直筒微锥；避开插肩袖、落肩、包臀短裙。
- **肩宽于胯** → 弱化肩端点：插肩/落肩、V 领深 U 领把视线收到中间、上身深色无肩部装饰；下装加体积（A 字、阔腿、浅色、口袋细节）。
- **腰线弱** → 两条路线选一：① 做结构（收腰剪裁、塞衣角、上下色块在腰处分界）；② 顺直筒（H 型直线 + 垂坠面料，不硬勒）。避开紧身针织包腰腹。
- **短腿** → 高腰、上下同色系、短上衣、露踝、鞋裤同色；避开中筒靴卡在小腿最粗处。
- **头显大肩显窄** → 加肩宽 + 发型加横向体积；避开紧贴头皮与高领。
- **胸大** → V 领、垂坠面料、收腰；避开高领、胸前大图案/口袋、硬挺 boxy。

### 第 4 步：出搭配

两套完整方案，覆盖用户实际场景（没给场景就用「日常通勤」+「周末」）。每套写清：上装 / 下装 / 鞋 / 外层 / 一句话说明为什么这套对着他的比例有效。

不要堆单名清单，不要列十个品牌。

### 第 5 步：自检

输出前过一遍：

- [ ] 有没有检查照片被服装 / 拍摄 / 生成修正过？被抹掉的指标有没有标「不可读」？
- [ ] 有没有把照片读数写成了测量结论？
- [ ] 有没有出现体型标签当结论（"你是梨形所以……"）？
- [ ] 每条处方是否带「为什么」？
- [ ] 有没有出现体重、减重、医美、好坏评价？
- [ ] 置信度是否标注？缺失数据是否说明？
- [ ] 两套搭配是否符合用户给的真实场景与预算？

### 第 6 步：回填

方案给完，末尾附一行：

> 穿完回一句就够：`好 / 中 / 差 + 一句话`

收到回填后追加到 `~/.outfit-body-fit/feedback.jsonl`，并更新 `known_good` / `known_bad`。下次会话先读 `profile.json` 和最近 5 条记录，已知数据不重问。

同一处方连续 2 次「差」→ 这条对该用户不成立，改走「冲突调和」里的备选，并在输出里说明改了什么。

完整约定见 [references/feedback-loop.md](references/feedback-loop.md)。用户不回就结束，不追问第二次。

## 硬性边界

- 不评价体重、不推荐减重、不评价长相、不建议医美。用户问「我是不是太胖」→ 不接这个判断，转成「穿衣能改的是视觉比例，体重不是这个 skill 的输入」。
- 用户表达身材焦虑时先接住情绪，再给可控的部分（比例、版型、颜色），不强化「遮」「藏」「遮丑」这类叙述。用「视觉收敛」「线条走向」「把重量上移」。
- 用户说明自己是未成年人 → 只给合身度、场合、舒适度建议，不做身材判读。
- 不推测健康状况、年龄、生育情况、职业收入。
- 涉及内衣尺码、束身衣、矫正带 → 不提供。
