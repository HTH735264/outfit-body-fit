# 量体穿搭 · outfit-body-fit

一个按**身材比例**给穿搭方案的 Agent Skill。不给你贴身材标签，给你可执行的版型处方。

## 它解决什么

「我这个身材适合穿什么」这句问题，绝大多数穿搭回答都在做两件事：贴标签（你是梨形 / 苹果形）和堆单品清单。前者把比例问题说成人身属性，后者不可复用——换一件衣服你就又不会了。

这个 Skill 换了个拆法：把身材拆成六个可计算的**比例指标**，每个指标对应一组**版型手法**，每条手法带「为什么」。学到的是判断方法，不是一份清单。

## 怎么工作

两个输入通道，分工不同：照片定方向，数字定幅度。

| 通道 | 输入 | 职责 | 数据完整度 |
|---|---|---|---|
| A 照片 | 全身 / 半身照 | 视觉轮廓走向、肩胯相对关系、上下身分割位置 | 中 / 低 |
| B 数字 | 肩宽、臀宽、腰围、臀围、身高（加胸围、腰高、会阴高、头宽、肩峰高更佳） | 可算的比例指标与幅度 | 高 |

**宽度和围度不能混用**：肩宽、臀宽是直线**宽度**；腰围、臀围是环绕**围度**。肩臀比只能由「肩宽 ÷ 臀宽」算，只给臀围时这一项判为不可读。

**照片定方向，数字定幅度。**

照片不做测量。手机广角会把画面中心放大、边缘拉伸，俯拍压短腿、仰拍拉长腿，宽松上衣会让腰线位置完全失真——用照片反推围度是错的。所以只有照片时，输出会明确标注「视觉印象，非测量结论」，并告诉用户补哪几个数就能升级精度。

六个指标：肩臀比、腰臀比、胸腰差、腿长比、躯干比、头肩比。每个指标映射到一组处方，完整表在 [`references/proportion-rules.md`](skills/outfit-body-fit/references/proportion-rules.md)。

## 安装

```bash
npx -y skills add HTH735264/outfit-body-fit -g --all
```

装到指定 agent：

```bash
npx -y skills add HTH735264/outfit-body-fit -g -a claude
```

手动安装：把 `skills/outfit-body-fit/` 整个目录复制到 agent 的 skills 目录（如 `~/.agents/skills/`、`~/.claude/skills/`、`~/.codex/skills/`）。

## 最短示例

```text
我 170，肩宽 36，臀宽 38，腰围 72，臀围 94，胸围 87，会阴高 76。平时通勤穿什么？
```

输出形态取决于输入：

- **数字档（B / B+）**——指标判读表、三条按影响排序的处方（每条带「为什么」）、两套完整搭配、雷区清单、数据完整度与待补数据
- **照片档（A）**——不做指标表，只给可观察的视觉方向、两条处方和搭配，并标注视觉印象
- **重度修图 / AI 生成图**——停止比例判读，只给版型与搭配建议，不输出判读表

注意「数据完整度」不等于「判断准确度」：前者只说明五个数齐不齐，后者上限在「中到高」，因为规则本身是经验性视觉判断。

只有一张照片时，把照片丢过去直接问「我这个身材怎么穿」即可，Skill 会走 A 档并主动降级标注。

## 边界

**做**：比例判读、版型处方、成套搭配、雷区、合身度判断（针对已穿的衣服）。

**不做**：

- 不评价体重、不推荐减重、不评价长相、不建议医美
- 不问内衣尺码、束身衣、矫正带
- 不推测健康状况、年龄、生育情况
- 用户说明是未成年人时，只给合身度与场合建议，不做身材判读
- 不推测身材类型标签当结论

用户表达身材焦虑时，先接住情绪，再给可控的部分：比例、版型、颜色。

## 规则来源与边界

三类来源要分开看：

**理论来源** — AICI 形象顾问课程、FIT 个人造型课程、《What Not to Wear》(Trinny Woodall & Susannah Constantine, 2002) 的比例方法论；结构化参考 [jeffreytse/grimoire-core](https://github.com/jeffreytse/grimoire-core)（MIT）。本仓库为中文重写。

**本仓库自设的启发式** — 全部具体数值分界（肩臀比 1.04 / 0.96、腰臀比 0.75 / 0.85、胸腰差 18cm、腿长比 0.45 / 0.48、头肩比 0.40）、照片影响三级分级、冲突调和的七组解法。这些是按造型实践归纳的经验值，**没有对上列资料做过逐条核对，也不是人体测量学标准**。数值落在边界附近时只描述为「接近均衡」，不强行归类。

**个体规则** — 来自用户反馈累积的调整，只对那个用户成立，存在本机，不进仓库。
